# Operating the origin

One binary, four systemd units, two planes:

* **front** (`pingora`) terminates TLS on the public port and reverse-proxies to
* **business** (`axum`, loopback) which owns every cache semantic: plans a
  ranged read, serves what is staged, opens one upstream stream per window.

The interface is **bytes** — flat `/<key>`, ranged `GET`/`HEAD`, no write verbs,
no CORS, no media awareness (ADR-0026). Big objects are staged **spans**: the
ledger is a policy map, the disk is the existence authority, and an object larger
than the magazine is served from its spans without ever being resident.

Working state lives in a repo-external handoff (`.zcode/handoff.md`, gitignored):
read it first in a new session, update it before any compaction. `docs/usage.md`
is the human version of this page; `deploy/README.md` indexes every instrument.

## Hard rules

1. **Credentials never enter the repo.** The node reads
   `/opt/origin-cache/origin-cache.env` (0600, generated by
   `deploy/oracle/env-file.sh`); docs/configs carry env-var *names* only. Adding a
   `*_env` name without setting it is a boot failure by design.
2. **The repo is CJK-free**, including commit messages — `hooks/pre-push`
   rejects it (percent-encode non-ASCII in fixtures).
3. **The clippy budget is 0** and only decreases; the same hook enforces it.
4. **Never point a trial binary at the live `cache_dir`.** A valid-but-wrong
   config quarantines the store and starts an empty one (pitfall 55). Rehearsals
   get their own dir and ports.
5. **Never rename `cache_dir`** — it holds the live database and every staged
   sidecar.
6. **Local browsers measure the LAB, not the CDN.** The workstation-to-edge leg
   stalls on its own (pitfalls 15/57); CDN numbers come from node-side probes,
   and a viewer-shaped load test from `deploy/lab/viewer/`.
7. **Bytes are accounted by the origin, not by cache labels**
   (`eo-cache-status` lies: pitfall 57, runbook "What the edge's cache label is
   worth").

## Closed questions — do not re-open

Origin placement (owner's decision: it does not move), ICP filing (not
applicable), plan upgrades (free tier by choice), client-side packaging
(ADR-0026: manifest/MSE is the client's), redundancy (ADR-0010: one node is
accepted), the open-ended-range shape and the CDN's range cap (both exonerated by
measurement), the fan-out service worker (works locally, hangs against the CDN —
pitfall 62; unsolved, not a blocker).

## Recipes

### Build and accept locally (no cloud)

```sh
cargo build --release --offline
bash deploy/lab/run-lab.sh --smoke     # PASS=35 FAIL=0, ~1 min
bash deploy/lab/run-lab.sh --quick     # PASS=75 FAIL=0, ~10 min (needs node+chromium+PW_DIR)
```
The suite refuses to run on a busy box (`load > 6` or a live `chromium`) because
its timing assertions include the machine. Browsers are sections 14/15.

### Update the node's binary

```sh
bash deploy/oracle/deploy-node.sh --yes     # package -> cross-build -> file+bogus-config gates -> install -> restart -> accept.sh, rolls back on failure
```
Config/unit changes are different: `sudo bash deploy/oracle/install.sh
<binary> [--keep-env] [--new-token]`, and plain `systemctl` may need
`sudo -n`. Then `bash deploy/oracle/accept.sh` and expect `VERDICT=PASS`.

### Take the origin's account

```sh
curl -s http://127.0.0.1:8080/_internal/healthz          # degraded? reasons? (and :8081 for nocache)
curl -s http://127.0.0.1:9090/metrics                    # front metrics :9091
bash deploy/oracle/fill-account.sh 300 200G              # per-key reqs/MiB/p50/p90 + counters
bash deploy/metrics-report.sh http://127.0.0.1:9090/metrics 30
journalctl -u origin-cache-efficient --since "1 hour ago" | sed 's/\x1b\[[0-9;]*m//g'
```
Snapshot the counters *before* a load and subtract: `backend_call_duration_seconds_count{op=open|stat}`,
`cache_serve_source_total`, `cache_session_total{sealed,chained,open_failed}`,
`cache_body_bytes_total`, `cache_unkeepable_trim_bytes_total`. One open per
window is the design target (measured: 1 per ~17.6 MB under random load).

### Run a viewer load test

```sh
PW_DIR=<playwright-core> node deploy/lab/viewer/player-swarm.mjs \
  --target <base-url> --page <same-origin page> --src <playlist> \
  --slots 10 --hours 4.5 --play-secs 5 --watch-secs 600 --fanout 0 \
  --out /mnt/hdd/.../sessions.jsonl        # write run data to the HDD: /tmp is tmpfs (pitfall 65)
node deploy/lab/viewer/swarm-report.mjs <sessions.jsonl> --bucket-minutes 20
```
Each session plays, seeks, watches and dies; the slot is refilled. Ten contexts
on an 8-core box reach load ~30, and then client-side failures are the box's
(pitfall 63) — always report load next to client numbers.

### Cold load on the origin

```sh
ssh <node> 'bash deploy/oracle/cold-load.sh 14400 8 5'   # 4 h, 8 parallel, 5 MiB random shards, loopback business plane
```
It separates cleanly in the log: loopback requests carry `xff=-`, edge pulls
carry the viewer's address.

### Give an fMP4 a playlist (fixture, not product)

```sh
node deploy/lab/viewer/fmp4-index.mjs --url <film-url> --minutes 30 --seg-secs 2 --out <dir>
```
It walks the file's own `moof`/`mdat` headers instead of downloading it (1811
reads / 113 MiB covered 3.2 GiB). Index a **prefix**, not a film: the edge pulls
a 1 MiB shard per little read, so a whole-film walk would pull ~half the object
(pitfall 64). The page, the worker and the playlist must be same-origin with the
media — there is no CORS.

## Definition of done for a change

`cargo test --offline` (expect 319) → a reverse validation (break it, name the
test that goes red) → `run-lab.sh --quick` (75/0) → node deploy + `accept.sh`
VERDICT=PASS → docs (ADR / spec / runbook / pitfalls / `deploy/README.md`) →
commit in English → push with `timeout 100` retries and verify
`git rev-parse HEAD origin/main` are equal → update `.zcode/handoff.md`.

## When it looks wrong

Start from `docs/pitfalls.md` by symptom: nothing arrives on a range request
(27/30), the store got quarantined (55), a `403` from outside (R4 working as
designed), a viewer that stalls (the runbook's MSE section — arithmetic before
blame), a slow first byte (provider `open`, already at its floor), a client
fixture that worked locally (62).
